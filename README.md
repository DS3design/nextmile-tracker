# Next Mile Tracker

A desk display for the ESP32-2432S028R "Cheap Yellow Display" that shows a runner's miles for the current year from their watch (Garmin, Apple Watch, Fitbit / Pixel, Polar; Strava if keys are supplied), a goal bar (beat last year by default, or a custom goal), and their last run. Built by DS3design for a Next Mile Apparel / Pacegiving raffle prize.

Boot: DS3design intro clip, Next Mile Apparel splash, then setup or the mileage screen.

## Layout

| Path | What |
| --- | --- |
| `firmware/` | PlatformIO project (Arduino, LovyanGFX). Envs `cyd_ili9341` and `cyd_st7789` for the two panel variants CYD clones ship with. |
| `firmware/data/` | LittleFS image: `intro.bin` (JPEG frames) and `nextmile.jpg` splash. |
| `docs/` | GitHub Pages: setup guide (`index.html`) the OAuth hand-off page (`link/`) and signed OTA releases (`fw/`). |
| `sim/` | Desktop renderer for the screens (`./build.sh`, needs `libsdl2-dev`). |
| `case/` | Laser-cut SVGs (red = cut, black = engrave) for 3 mm basswood. Generated by `tools/make_case.py`. |
| `card/` | Printable 4x6 in setup card. |
| `tools/` | Generators for fonts, assets, root certificates, case and card. |

## Data sources

| Brand | How it links | Needs | Notes |
| --- | --- | --- | --- |
| Garmin | Runner pastes a Personal API key | nothing | Key lasts up to 1 year. Garmin says the personal API "is not intended for commercial applications serving multiple end users". |
| Polar | OAuth (Connect with Polar) | free AccessLink client | Only exercises from after linking, last 30 days; runner enters earlier miles. |
| Fitbit / Pixel | OAuth (Google Health API) | Google Cloud OAuth client | Unverified apps: 100 users max. More needs verification + yearly security assessment. |
| Apple Watch | iPhone Shortcut POSTs `/api/apple?t=<token>` | nothing | Phone must be on home WiFi when it runs. Untested. |
| Strava | OAuth | Strava API app (needs a subscription) | Hidden unless keys are set. |

OAuth keys go in `firmware/src/secrets.h` (copy `secrets.example.h`; git-ignored). A brand with empty keys is hidden from the picker. Every OAuth app's redirect URL is `https://ds3design.github.io/nextmile-tracker/link/`.

## OTA updates

Boards check `docs/fw/manifest.json` 3 minutes after boot and then daily, and only install an image whose SHA-256 is signed by the DS3design key (ECDSA P-256). A new version that doesn't stay up for 2 minutes 3 boots in a row is rolled back to the previous slot.

```sh
python3 tools/release.py keygen       # once; private key -> ~/.nextmile/ota_signing_key.pem (back it up!)
python3 tools/release.py publish 2    # build + sign version 2 into docs/fw/, then commit and push
```

## Flashing

```sh
cd firmware
pio run -e cyd_ili9341 -t upload      # or cyd_st7789 if colours/orientation look wrong
pio run -e cyd_ili9341 -t uploadfs    # intro clip + splash
```

## How linking works

The tracker serves `http://<ip>/link` (brand picker). OAuth brands go to the provider's authorize page with `state=<tracker ip>|<brand number>`. The provider redirects to `docs/link/` on GitHub Pages, which forwards the one-time code to `http://<ip>/exchange` on the home network. The tracker swaps it for tokens and refreshes them itself from then on. Syncing reads the latest 30 activities every 30 minutes and re-reads the whole year once a day, so edits and deletions show up.
